# All source operator validation

## Revision and scope

Based on merged main `7583876ae99b48917fffde9a21924df05cec393e`, tree
`a3ca1637f36681304863543a75ffb2292fc9cc99`. The prepared lexical package was
reconstructed and reversed to that exact base tree before fresh execution.
The remote design-only commit precedes implementation. All data below was measured
September 15, 2026 with Node v22.16.0 on Linux x64 and Chromium 144.0.7559.96.

This combines lexical infix declarations/relative precedence with source defaults
for 13 binary forms and two prefixes. Unary bindings and first-class captures,
Boolean and pipeline rebinding, a checked text snapshot and a core inventory entry
complete the scope. The compiler retains 11 scalar-instruction function values,
parsing, type checking, staging, JTE, memory and authority mechanisms. It does not
claim that mathematical arithmetic or syntax punctuation is implemented from nothing.
The existing 30 callable primitives and four optional source-prelude functions remain.

The tokenizer/parser change; the stager gains bounded caches for closed library
factories and parameter-only scalar applications. There is no new inference,
AD, JTE rule, Wasm instruction, ABI layout, host import or dependency. The existing
matrix-free `lib/operators.ass`, root README and earlier feature implementations
are retained. `lib/expression-operators.ass` is the new editable source of truth.

## Semantics, boundaries and resource checks

Tests exercise every default expression role, all 13 binary rebindings, independent
unary/binary minus, Boolean/numeric interpretations of the same policy, first-class
prefix captures, nested restoration and previously captured functions. The default
Boolean truth tables, skipped trapping operands and type checking of unused
operands are checked. Pipes retain data-first trailing-argument placement even
when their source implementation is replaced. Legacy expressions also use source
factories; legacy declarations do not gain local notation syntax.

Scalar negation preserves both zero signs and infinities; numeric NaN comparisons
and ordinary source differentiation remain tested across eight modes. Effects
cannot be invoked through a prefix/infix alias. Previously performed scalar values
can be captured without replaying a host call. Default source factory names cannot
be captured by similarly named user functions. Renaming and changing an explicitly
linked factory changes ordinary application results, not a compiler-selected body.

The factory text cannot circularly use the default operators it defines and must
be closed over its scalar parameter/local bindings. The small compiler bootstrap
record is the only raw scalar-operator AST generated by expression elaboration.
Core-only mode retains basic expression syntax while still rejecting unlinked
sum/grad/jvp/vjp. Generated nodes are charged to the existing 50,000-node cap;
lexical operator counts and nesting limits remain bounded.

The first implementation exceeded the old maximum-equation staging allowance.
It rebuilt a closed bootstrap dictionary whenever a generated helper ran. A
compilation-local factory cache removes that repeated work. A second cache avoids
reconstructing identical parameter-only scalar expressions that the scalar graph
constructor already hash-conses. Calls, projections, records, blocks, free captures
and non-scalar arguments are excluded. A pipe that constructs two scans still
creates two independent machine identities. No default expansion allowance or
existing maximum-graph test was relaxed. All original maximum-proof tests pass.

## Costs and limitations

The policy example evaluates to {allowed:true,score:0.5} at input
[0.25,0.5,0.125], emits no loops, needs zero intermediate data buffers, and has a
1,090-byte module in the documented default build. Returned records still need
ordinary ABI descriptors; source syntax is not zero compiler work. Factory
elaboration adds nodes and type constraints, and small custom expansion limits
may behave differently. The new caches reduce redundant staging, not runtime
array work. No benchmark establishes a throughput or compile-time speedup.

The compiler still owns built-in precedence groups, first-argument pipe parsing,
unary binding power, application, field selection, arrows and delimiters. Custom
infix relations are declared in source, but this is not an arbitrary parser macro
facility. Custom unary/postfix grammar, type-directed global overload resolution,
operator sections and Unicode glyphs are not added. Pure lazy demand does not let
an operator suppress parsing/type/AD validity checks on its operands.

Browser registration covers both harnesses; only the engine path completed.
No HTTP policy was bypassed. Other engines, independent formal auditing,
proof-assistant verification and empirical readability studies were not performed.
Publication identifiers, exact tree comparison and fresh GitHub CI are recorded
separately in the PR discussion, not inferred from these local checks.
